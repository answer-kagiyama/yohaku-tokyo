# Product — YOHAKU TOKYO

> 東京の「何もない」を、データで見つける。

## 1. What

YOHAKU TOKYO は、東京都・区市町村のオープンデータを横断し、
**駅周辺 500m に「目的地となりうる施設・機能」がどの程度存在するか** を数値化するプロダクトである。

「何もない駅」は企画上の説明語であり、プロダクト名には使わない。
内部的には「何もない」を次のように定義する。

> 東京都・区市町村のオープンデータ上で、駅周辺に存在する“目的地となりうる施設・機能”が相対的に少ない状態

主観的な断定ではなく、**相対的・決定論的・出典付き** の指標として扱う。

## 2. Core value

| 価値 | 内容 |
| --- | --- |
| 発見 | 観光ガイドに載らない「余白の駅」を見つける |
| 説明可能性 | すべてのスコアに raw 値・percentile・出典が付く |
| 再現性 | 同じ入力データからは常に同じスコアが出る（AI が最終スコアを決めない） |

## 3. Key term — YOHAKU SCORE（何もなさ指数）

- 0〜100。**高いほど「何もない（余白が大きい）」**。
- 各特徴量（観光・文化・公共施設・公園・図書館・駅利用者数）を percentile rank で 0〜100 に正規化し、
  「少なさ」（`100 - percentile`）を重み付き平均する。
- 重みは MVP 仮仕様（`docs/scoring.md` で確定予定）:

| feature | weight |
| --- | --- |
| tourismLow | 25% |
| cultureLow | 20% |
| publicFacilityLow | 15% |
| parkLow | 10% |
| libraryLow | 10% |
| stationUsageLow | 20% |

## 4. Users

- 都市散策・街歩きが好きな人（「何もない駅で降りてみたい」）
- 都市・地域データに関心のある人（出典まで追いたい）
- 編集者・ライター（記事ネタとしての駅探し）

## 5. MVP screens

| 画面 | 目的 |
| --- | --- |
| Home | 世界観を一発で伝える。注目駅・指数の説明・methodology 導線 |
| Station Explorer | 駅一覧。検索・ソート・スコア・dominant feature。desktop は table 寄り |
| Station Detail | 「駅のカルテ」。スコア・特徴量バー・raw/percentile・出典・methodology |
| Methodology | 指数の算出方法と限界の説明 |

## 7. Non-goals (MVP)

- DB / 認証 / クラウドデプロイ
- AI チャット中心の UX
- AI による最終ランキング生成
- 主観的レビュー・口コミの収集

## 8. Honesty rules

- **データ取得失敗を「施設数 0」と解釈しない。** 欠損は欠損として表示する。
- fixture（サンプル）データで表示している間は、UI 上でその旨を明示する。
