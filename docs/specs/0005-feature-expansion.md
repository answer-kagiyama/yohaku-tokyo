# Spec 0005 — Feature expansion（Step 7: culture / publicFacility / tourism / library / stationUsage）

- Status: Implemented
- Related: spec 0002〜0004, ADR 0005, ADR 0008

## 1. Scope

park と同じ経路（discover → ingest → aggregate）で culture・publicFacility・tourism・library を実データ化し、
stationUsage（駅利用）を東京都統計年鑑の駅別表から取得する。これで fixture の特徴量はなくなる。

## 2. 実データで判明した問題と、入れたルール

| 問題（実測） | ルール | 設定 |
| --- | --- | --- |
| 「都立文化施設**事業一覧**」（イベント）、「**資源回収箱**設置公共施設一覧」、「**移動図書館**巡回場所」が accepted | 除外語の追加（feature 固有 + 全体）| `exclude_keywords`, `global_exclude_keywords` |
| 行政基礎資料集・観光客数等実態調査など統計資料が review に大量 | 全体の除外語に追加 | `global_exclude_keywords` |
| `観光ポイント_緯度` のような接頭辞付き列名を検出できない | `_` 区切りの末尾一致も列名候補とする | `inspect.schema.find_field` |
| 404 のリソースを 3 回リトライ | 4xx（429 以外）はリトライしない | `http` |
| 公共施設一覧に図書館・公園が含まれ二重計上 | 施設名の末尾（〜図書館、〜図書館分室 等）で除外。「神田公園出張所」のような地区名は除外しない | `exclude_facility_names` |
| 千代田区の公共施設一覧は**資産台帳**（便所・倉庫・区営住宅・旧〜・階別事務室）で、台東区は区民館のみ。区のリストの粒度差をそのまま数えると「区のデータの作り方」を測ってしまう | publicFacility の概念を「地域の集会・交流施設」に揃える（名前に区民館・出張所・会館・ホール等を含むもののみ）+ 非目的地の除外 + 同一建物の統合 | `include_name_keywords`, `exclude_name_markers`, `same_place_m` |
| 文化財一覧に **※非公開**・**無形文化財**（技術）・同じ寺社の所蔵品が多数 | 非公開・無形を除外し、30m 以内は同じ「場所」として 1 件に数える | `exclude_name_markers`, `exclude_categories`, `same_place_m` |
| 千代田区の公共施設に**都外（軽井沢）**の施設 | 住所が他県で始まれば `outside-tokyo`。位置不明扱いにしない（どの都内駅の圏内にも入らない）| `geo.geocode.is_outside_tokyo` |
| 台東区の文化財 190 件中 7 件が住所「東京都台東区」のみ | 位置不明が区全体の 5% 以下なら covered とみなし、件数を evidence に残す（500m 圏は区面積の 1 割未満のため、圏内に入る期待値は通常 1 件未満）| `pipeline.yaml: coverage.unlocated_tolerance` |
| 文京区は文化財一覧がなく「文化・スポーツ施設」のみ | エージェントの判断で overrides に culture として採用し、ユーザーがレビューして承認（2026-09-28）、スポーツ施設は名前で除外 | `overrides.json: culture/<id>` |

overrides は `<feature>/<datasetId>` で feature 単位に指定できる（同じデータセットが複数 feature の候補になるため）。

## 3. tourism（観光）の欠損

千代田区はカタログに観光施設のデータセットを公開していない（文京区も同様）。
対象 5 駅はすべて 500m 圏に千代田区が掛かるため、**上野以外の 4 駅の tourism は欠損（null）**。
0 で埋めず、スコアは残りの特徴量の重みを再正規化して算出する（coverage 0.75）。UI で欠損と明示する。

## 4. stationUsage（駅利用）

| 項目 | 内容 |
| --- | --- |
| 出典 | 東京都統計年鑑「運輸・観光」の駅別表（JR の駅別乗車人員 / 私鉄・地下鉄の駅別乗降車人員）|
| 探索 | カタログ検索で東京都総務局の「東京都統計年鑑 … 運輸」パッケージのうち最新年のものを選び、リソース名に「駅別乗車人員」「駅別乗降車人員」を含む表を使う（URL を手書きしない）|
| 指標 | **1 日平均乗車人員**（全社・全線の合算）。JR は乗車人員のみ公表のため、比較可能な乗車人員に揃える（元の「乗降人員」から変更）|
| 計算 | 最新年度の `乗車人員／総数`（千人/年）を駅名の完全一致で合算 × 1000 ÷ 年度の日数 |
| 照合 | 駅名の完全一致。仲御徒町・上野御徒町・京成上野など別名の駅は含めない |
| 欠損 | どの表にも駅名がなければ null |

evidence は路線別の内訳（会社・路線・年間乗車人員）を持つ。

## 5. 比較不能（有効値 3 駅未満）

tourism は 5 駅中上野だけが値を持つ。1 駅だけで順位は作れないため、`docs/scoring.md` §2 を改訂し、
有効値が 3 駅未満の特徴量は全駅で percentile = null（比較不能）とした。UI では「欠損（データなし）」と
「比較不能（値はあるが比較できない）」を区別して表示する。
