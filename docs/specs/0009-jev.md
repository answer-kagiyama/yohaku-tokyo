## 1. Jev とは（調査結果）

TypeSafe AI 社の「System One モデル」。**文章を生成せず、あらかじめ定義した選択肢の中から判断を返し、確率と確信度を付ける**。
2026-09-15 発表、09-21 にウェイトリスト撤廃（一般提供）。

| 項目 | 内容 | 出典 |
| --- | --- | --- |

| 入力 | `state`（文字列・オブジェクト・配列）+ `questions`（名前付きの質問マップ）+ `model`（`jev-latest`）| 公式 docs |

- **日本語への対応**（言語の記載なし）。国内の試用記事では日本語の判定自体は動いているが、精度の体系的な評価はない
- 同じ入力で同じ出力が返るか（温度・シードの指定はない）
- レート制限の具体値、入力長の上限

## 2. このプロジェクトでの使いどころ

Jev の「決められた選択肢から、確信度付きで判断する」性質は、今ルールで書いている判定とそのまま対応する。
**スコアの計算には使わない**（ADR 0004）。判定は必ず分類器名・モデルの版・確信度とともに記録し、Jev がなくても pipeline は完走する（ADR 0003）。

| # | 用途 | 今のルールベース | Jev の質問（案）| 入力（`state`）| 効果 |
| --- | --- | --- | --- | --- | --- |
| A | **データセットの適合判定** | キーワード・除外語・一覧語（`discover/evaluate.py`）| choice: どの feature の施設リストか（park / culture / publicFacility / tourism / library / none）+ noul: 実在の場所の一覧か | タイトル・説明・リソース名・列名・サンプル 3 行 | 「要確認」約 250 件の自動振り分け。統計・イベント・遺跡一覧などの誤採用を減らす |
| B | **列の意味の特定** | 列名の候補リスト（`inspect/schema.py`）。`館名`・`ページタイトル`・`タイトル` を人手で追加してきた | choice（列ごと）: 名称 / 住所 / 緯度 / 経度 / 種別 / その他 | 列名 + 各列の値 3 件 | 列名の揺れによる取得失敗をなくす（ルールで見つからないときのみ）|
| C | **施設の分類・目的地判定** | 施設名の末尾・目印・種別の語（`ingest.matches_feature`, `exclude_*`）| choice: feature（none を含む）+ noul: 一般の人が訪れる目的地か | 施設名 + 種別 + データセット名 | 混在リストの振り分け、便所・倉庫・非公開・無形などの除外を語彙に頼らず判定 |
| D | **補助的な意味特徴** | なし | score: 観光地らしさ / 住宅地らしさ / 文化の厚み など（5 段階）| 駅の 500m 圏の施設名一覧 | `stations.json` の `semantic` に表示用として格納。スコアには入れない |

優先順位: **A → C → B → D**。A は入力がすべてコミット済みで、効果（要確認の削減）がすぐ見える。
C は施設データ（`data/interim`）を使うため、ローカル作業の間は問題ないが、クラウドへ移る前に施設データの共有方法を決める必要がある。

### 使い方の原則

- **確信度で使い分ける**（公式の confidence-gated routing パターン）: 確信度が高いときだけ Jev の判定を採用し、低いときはルールの結果か「要確認」に残す。しきい値は検証で決める。
- **人の判断が最優先**: `overrides.json` は Jev より優先する。
- **判定は保存して再利用する**: 入力のハッシュをキーに `data/processed/semantic/<用途>.json` へ保存し、同じ入力では API を呼ばない。
  再現性（同じ入力で同じ出力が返るかが未確認）と費用の両方のため。保存ファイルはコミット対象。
- **ルールとの差分を記録する**: ルールと Jev の判定が食い違ったものは manifest / report に残し、人が確認できるようにする。

### 3.2 指標と合格の目安

| 指標 | 目安 |
| --- | --- |
| 正解率（ルールベースとの比較）| ルールより明確に高い、またはルールが苦手な事例で正しい |
| 確信度の較正 | 確信度 ≥ しきい値の判定の正解率が 95% 以上になるしきい値が存在する |
| 再現性 | 同じ入力を 3 回送って答えが変わらない割合 |
| 指示の言語 | `instructions` / `criteria` を日本語で書いた場合と英語で書いた場合の差 |
| 費用・速度 | 評価全体の入力トークン数と所要時間（想定: $0.01 未満）|

不合格（日本語で実用にならない）の場合は、Jev は導入せず RuleBased のまま進める。その判断も ADR に残す。

## 4. 実装方針（検証で合格した後）

- `pipeline/src/station_pipeline/classify/`（空パッケージ）に `SemanticClassifier` プロトコルと `RuleBasedClassifier`（現行ロジックを移設）/ `JevClassifier` を置く。
- HTTP は SDK（`typesafe-sdk`）を使う（429/529 の自動リトライのため）。依存追加の理由は ADR 0003 に記録する。
- API キーは環境変数 `TYPESAFE_API_KEY`（`.env`、コミットしない）。未設定なら自動で RuleBased のみ。
- テストは fake transport（ネットワークなし）。実 API を叩く評価は `make jev-eval` として分け、CI では実行しない。

## 6. 検証結果（2026-09-28, jev-1.13.0）

`pipeline/scripts/jev_eval.py`（実 API）、評価セット `pipeline/tests/fixtures/jev_eval/`。
568 回の呼び出し、入力 34.8 万トークン、**費用 $0.015**、所要 30 秒（4 並列）、応答の中央値 0.18 秒。

| 評価セット | 件数 | ルールのみ | Jev のみ（日本語指示）| Jev（英語指示）| **組み合わせ** |
| --- | --- | --- | --- | --- | --- |
| データセットの判定（用途 A）| 53 | 86.8% | 75.5% | 73.6% | **98.1%** |
| 施設の判定（用途 C）| 68（曖昧 21 件を除く）| 85.3% | 86.8% | 86.8% | **98.5%** |

- **再現性**: 同じ入力を 3 回送って答えが同じだった割合は施設 100%、データセット 98.1%。
- **日本語**: 指示を日本語で書いても英語で書いても精度は同じ。日本語の指示でよい。

### 分かったこと

| 観察 | 対応 |
| --- | --- |
| Jev はタイトルにつられ、統計表（「公園の数と面積」「〜の推移」「観光客数等実態調査」）もそのカテゴリの一覧と答える | 同時に聞く noul「場所を 1 行ずつ並べた一覧か」が統計・資料集では 0.04〜0.34、本物の一覧では 0.6〜0.8 と分離する。**noul ≥ 0.45 のときだけ Jev のカテゴリを採用** |
| ルールは語彙にない一覧（「公園一覧」「公園・緑地」「公園データ一覧」）を「要確認」に残す | Jev は確信度 1.00 で正しく park と判定。**ルールの「要確認」だけを Jev に回す**（ルールの採用・不採用は維持）|
| Jev は「※非公開」「無形文化財（工芸技術）」「旧〇〇」「〇階事務室」を見落として文化・公共施設と答える | 明確な語による除外（`exclude_name_markers` / `exclude_categories`）は**ルールを先に適用**し、残りを Jev で分類 |
| ルールは「神田公園出張所」（地区名）を公園と誤る、語彙にない「みなと科学館」「上野動物園」「西郷隆盛像」を拾えない | Jev のカテゴリ判定で解決 |
| 施設の noul「目的地として訪れられるか」は、トイレ・小学校・保育園にも 0.8 前後を返す（文字どおり「訪れることができるか」と解釈）| **この noul は使わない**。目的地かどうかはカテゴリの choice（none を含む）で判断する |

### 注意（この結果の限界）
- 評価セットは小さく（121 件）、しきい値 0.45 は同じデータで決めた。実装後、新しい事例で確認し直す。
- 正解ラベルは Claude が実データを見て付けたもの（overrides の 2 件もエージェントの判断で、後にユーザーが承認）。**ユーザーによる抜き取り確認が必要**。
- 施設の「ルールのみ」は、各 feature のフィルタを順に当てた近似（実際の pipeline はデータセットの feature ごとに判定する）。

### 結論
Jev 単体ではルールに置き換わらないが、**ルールが決めきれない部分だけを Jev に任せる組み合わせ**で大きく改善する。§4 の方針で実装に進む:
1. discover: ルールで `review` になったデータセットを Jev で判定（noul ≥ 0.45 かつ確信度で採否）。人の overrides は最優先。
2. ingest: 混在リスト（`rowFilter`）の行分類を、ハード除外ルール → Jev のカテゴリ判定、の順にする。

## 7. 実装仕様（v1）

### 7.1 構成

| モジュール | 役割 |
| --- | --- |
| `classify/base.py` | `SemanticClassifier` プロトコル（`judge_dataset` / `judge_facilities`）と判定の型 |
| `classify/jev.py` | `JevClassifier`（urllib で POST、429/529 は指数バックオフ、4 並列）。判定キャッシュ付き |
| `classify/cache.py` | 入力（state + questions）の sha256 → 応答。`data/processed/semantic/jev-cache.json`（コミット対象。同じ入力では API を呼ばない）|
| `classify/__init__.py` | `load_classifier()`: `TYPESAFE_API_KEY` があり `pipeline.yaml` の `semantic.classifier: jev` なら Jev、なければ `None`（ルールのみ）|

SDK（`typesafe-sdk`）は使わず、既存の `http.py` と同じく標準ライブラリで実装する（依存を増やさない。リトライは自前）。

### 7.2 discover: 要確認データセットの判定（§6 の結論 1）

対象: ルールの判定が `review` のエントリ。入力は タイトル・提供組織・リソース名・列名。

| Jev の答え | 条件 | 結果 |
| --- | --- | --- |
| そのエントリの feature | 確信度 ≥ 0.7 かつ「場所の一覧」noul ≥ 0.45 かつ location ≥ 0.8（位置が使える）| **accepted** |
| そのエントリの feature | 上の条件のうち location だけ満たさない | review のまま（Jev の判定は記録）|
| 別の feature / none、または noul < 0.45 | 確信度 ≥ 0.7 | **rejected** |
| それ以外 | — | review のまま |

- エントリに `semantic: {classifier, model, category, confidence, listScore}` を記録し、reason に「Jev: …」を追記する。
- overrides（人のレビュー済み判断）は Jev より優先する（適用順: ルール → Jev → overrides）。
- Jev が採否を変えたデータセットは、次回ユーザーに一覧で報告する（`docs/status.md` のレビュー待ち）。

### 7.3 ingest: 混在リストの行分類（§6 の結論 2）

対象: `rowFilter: true` のデータセット。
明確な除外ルール（`exclude_facility_names` / `exclude_name_markers` / `exclude_categories`）を先に適用し、
残りの行を Jev でカテゴリ分類して、確信度 ≥ 0.5 でそのデータセットの feature と判定された行だけを数える。
Jev がない場合は従来のキーワード照合（`matches_feature`）。report に分類器名と除外件数を残す。

### 7.4 設定（`pipeline/config/pipeline.yaml`）

```yaml
semantic:
  classifier: jev          # jev | none
  dataset: { min_confidence: 0.7, min_list_score: 0.45 }
  facility: { min_confidence: 0.5 }
```

## 8. v1 の実行結果（2026-09-28）

- discover: 要確認 190 件 → 68 件。採用 3（うち混在リスト 2 件は `rowFilter` 付き）、不採用 92（統計・利用集計・調査・資料集）。
  判定 150 回、費用は数セント未満。一覧は `docs/reviews/2026-09-28-jev-datasets.md`（ユーザーのレビュー待ち）。
- 実装中の修正:
  - 混在リスト（区内施設一覧・公共施設一覧）を「該当なし」として捨てていた → 選択肢に `mixed` を追加し、`rowFilter` 付きで採用
  - 文化財一覧（「一覧」の値 0.38〜0.47。所蔵品が混ざるため）を捨てていた → 不採用は「一覧」< 0.3 のみ、0.3〜0.45 は要確認のまま
- ingest: 混在リスト 520 行を Jev で分類。ルールでは拾えなかった都立庭園（六義園・旧古河庭園・浜離宮恩賜庭園など）を公園として数えるようになった。
- 混在リストから該当行が 0 件になったデータセットは `no-matching-rows` とし、区のデータが揃っている根拠にしない（0 件と欠損を区別するため）。
  文京区「文化・スポーツ施設」は Jev の判定で文化 0 件（ホール・会館は公共施設）となり、文京区の文化は欠損扱いになった。
- 駅への影響: 判定 20 → 19 駅（巣鴨が判定不能に）。御徒町・秋葉原の文化が欠損。浜松町の公園 8 → 9。他の駅の変動は 1 点未満。
- 残る課題: 要確認の多くは、カテゴリは判定できても位置情報（座標・住所）が使えないもの。
