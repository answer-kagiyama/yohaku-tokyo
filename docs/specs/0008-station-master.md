# Spec 0008 — Station master & 山手線 30 駅（Step 10）

- Status: Implemented
- Related: ADR 0010, spec 0003〜0006

## 1. Decisions（ユーザー判断 2026-09-28）

| 論点 | 決定 |
| --- | --- |
| 駅マスタの出典 | 国土数値情報「鉄道データ」（N02, 国土交通省, CC BY 4.0）|
| 対象駅 | 山手線 30 駅 |

## 2. Station master

| 項目 | 取得元 |
| --- | --- |
| 駅名 | `pipeline/config/stations.yaml`（人が定義するのは駅名のみ。座標・路線は書かない）|
| 座標 | N02 の駅（LineString）のうち、対象事業者（東日本旅客鉄道）の同名駅の中点の平均 |
| 路線 | N02 のグループコード（300m 以内の同名駅）が同じ全事業者の路線 |
| 英語名・ID | 東京都統計年鑑の JR 駅別表の英語表記（`Takanawa Gateway` → `takanawa-gateway`）|
| 所在区市町村 | 駅座標の逆ジオコーディング |
| 圏内の区市町村 | 500m 圏の 25 点サンプリング（spec 0004）|

実データで確認した事実: N02 の「山手線」は法定区間（品川〜新宿〜田端）の 17 駅のみで、
残り 13 駅は東海道線・東北線として登録されている。したがって「山手線 30 駅」は駅名リストで定義する。

出力: `data/processed/stations.master.json`（fixture と同じ形。raw は空）。

## 3. Geocoding scope の自動化

`pipeline.yaml` の `geocode.scope` を `auto` にし、駅マスタの「圏内の区市町村」の和集合 + `extra`（東京都建設局など）とする。
駅を増やしても設定の手直しが要らない。

## 4. Pipeline

```text
make data:
  stations  → stations.master.json（N02 + 年鑑 + 逆ジオコーダ）
  ingest    → 施設（ジオコーディング範囲は master から自動）
  aggregate → 駅ごとの 500m 集計（master の駅）
  ridership → 駅利用（master の駅）
  build     → stations.json（master + aggregates）
  export    → Web
```

`data/fixtures/stations.raw.json` はテスト用 fixture として残す（`make data` では使わない）。

## 5. 30 駅への拡大で判明した問題と対応

| 問題（実測） | 対応 |
| --- | --- |
| 豊島区の文化財住所が `豊島区長崎1-9-2　金剛院`（住所 + 全角空白 + 場所名）で、345 件がジオコーディング不能 | 番地の後ろの数字を含まない語を場所名として除去（`geo.geocode.strip_trailing_place_name`）→ 17 件に |
| 品川区の「文化財」は遺跡一覧（遺跡名・時代・出土遺物）で名称列がなく取得失敗 | 埋蔵文化財は目的地ではないため overrides で不採用（culture の除外語と同じ方針）|
| 新宿区の CSV は UTF-16（BOM 付き）で読めない | BOM で UTF-16 を判定 |
| 港区「公共施設情報」は種別ごとに 14 ファイル。1 ファイル（学校）だけ選んでいた | リソース名が feature のキーワードに一致するファイルを優先（例: 公園 →「公園・児童遊園・緑地」）。リソース名の一致を semantic 0.7 とする |
| タイトルに概念語がない混在リスト（施設一覧・公共施設情報）| manifest に `rowFilter: true` を付け、ingest で施設名・種別に feature のキーワードを含む行だけを数える（RuleBasedClassifier の行単位分類, ADR 0003）|
| 北区はカタログに施設系データがほぼない（全 7 件: AED・Wi-Fi のみ）| 欠損のまま（推測しない）|

## 6. 判定不能の扱い（ユーザー判断 2026-09-28）

厳密なルール（有効な特徴量の重み ≥ 50%）を維持する。30 駅中 20 駅を順位付けし、10 駅（渋谷・新宿・原宿・代々木・恵比寿・
品川・目黒・駒込・田端・西日暮里）は「判定不能」として、どの区のどのデータが足りないかを UI に表示する。
面積割合で緩める案は試算で効果が小さかった（許容 20% で 20 → 22 駅）。原因の多くは駅の所在区自体にデータがないため。
